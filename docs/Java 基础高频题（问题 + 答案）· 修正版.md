- # Java 基础高频题（问题 + 答案）· 修正版

  ---

  **1. final、finally、finalize 的区别？**

  - **final**：关键字，修饰变量/方法/类，表示"不能改"
    - `final int x = 10;` 变量不能重新赋值
    - `final void method() {}` 方法不能重写
    - `final class MyClass {}` 类不能继承
  - **finally**：关键字，配合 try-catch，**无论是否异常都执行**，常用来关资源
    - 唯一不执行的情况：`System.exit()`
  - **finalize**：`Object` 类的方法，**对象被 GC 回收前调用**，做最后清理
    - 现在不推荐用（执行时机不确定、可能延迟回收），推荐 try-with-resources

  ---

  **2. Collection 和 Collections 的区别？**

  - **Collection**：**接口**，单列集合的根接口，List、Set、Queue 都继承它
    - 注意：Map 不是 Collection 的子接口
  - **Collections**：**工具类**，提供操作集合的静态方法
    - `sort()` 排序、`reverse()` 反转、`max()`/`min()`、`shuffle()` 打乱、`synchronizedList()` 转线程安全、`unmodifiableList()` 转不可变

  ---

  **3. String、StringBuilder、StringBuffer 区别？为什么 String 不可变？**

  - String：不可变，线程安全，拼接慢
  - StringBuilder：可变，线程不安全，快
  - StringBuffer：可变，线程安全（方法加 synchronized），比 StringBuilder 慢
  - String 不可变原因：类被 final 修饰，内部 char 数组也是 final，且不提供修改方法

  ---

  - **4. `String s = "a"` 和 `new String("a")` 有什么区别？== 和 equals 哪个为 true？**
    - `"a"` 存在字符串常量池，池里已有则复用；`new String("a")` 在堆里新建对象
    - `==` 对基本类型比值，对引用类型比地址；`equals` 默认比地址，String 重写后比内容
    - `s1 == s2`（都是 `"a"`）为 true；`s1 == s3`（一个是 new）为 false；`s1.equals(s3)` 为 true

  ---

  **5. == 和 equals 的区别？重写 equals 为什么必须重写 hashCode？**

  - `==` 比地址（基本类型比值），`equals` 默认比地址，可重写为比内容
  - hashCode 的约定是：equals 相等的两个对象，hashCode 必须相等。**不重写 hashCode，两个 equals 相等的对象可能算出不同的 hashCode，违反约定**，导致 HashMap/HashSet 把它们当成两个不同的 key，出现重复元素

  ---

  **6. 受检异常和运行时异常的区别？Error 一般处理吗？**

  - 受检异常：编译器强制处理（try-catch 或 throws），如 IOException
  - 运行时异常：不强制处理，如 NullPointerException
  - Error 不处理，如 OOM、StackOverflowError，程序处理不了

  ---

  **7. final、static、abstract 各有什么用？**

  - final：最终的，变量不能改、方法不能重写、类不能继承
  - static：静态的，属于类不属于对象，不用 new 就能用，所有对象共享
  - abstract：抽象的，方法只声明不实现，子类必须实现

  ---

  **8. 接口和抽象类的区别？什么时候用哪个？**

  - 接口：描述能力，可多实现，不能有构造方法，变量只能是常量
  - 抽象类：描述同类，只能单继承，能有构造方法和方法体
  - 描述能力用接口，描述同类事物用抽象类

  ---

  **9. String 的 intern() 是干什么的？**

  - 把字符串放进常量池，返回池里的引用
  - 池里已有则直接返回，没有则放入
  - 作用：让相同内容的字符串共享，省内存

  ---

  **10. 常问 HTTP 状态码有哪些？**

  - 200 成功；201 创建成功；204 成功无内容
  - 301 永久重定向；302 临时重定向；304 未修改（命中缓存）
  - 400 参数错误；401 未认证；403 无权限；404 找不到；405 方法不对；429 请求太频繁
  - 500 服务器内部错误；502 网关错误；503 服务不可用；504 网关超时
  - 易混：401 没认证，403 认证了但没权限；500 后端自己报错，502 网关连不上后端

  ---

  **11. SpringBoot 自动装配是什么？**

  - `@SpringBootApplication` = `@SpringBootConfiguration` + `@EnableAutoConfiguration` + `@ComponentScan`
  - 流程：启动类加载 `@SpringBootApplication` → `@EnableAutoConfiguration` 找 `META-INF/spring.factories` → 加载自动配置类 → 按 `@ConditionalOnXxx` 条件判断是否生效
  - `@ConditionalOnClass`：有这个类才装配；`@ConditionalOnProperty`：配置了属性才装配
  - starter 预置了依赖 + 自动配置，所以一行就能引入

  ---

  **12. SpringMVC 执行流程？**

  - 请求 → DispatcherServlet（前端总控）→ HandlerMapping（找 Controller 方法）→ HandlerAdapter（执行）→ Controller 业务 → 返回 ModelAndView / @ResponseBody 转 JSON → 视图解析/序列化 → 响应
  - 核心组件：DispatcherServlet、HandlerMapping、HandlerAdapter、ViewResolver
  - `@RestController` = `@Controller` + `@ResponseBody`

  ---

  **13. MyBatis 的 #{} 和 ${} 区别？**

  - `#{}`：预编译占位符，编译成 `?`，防 SQL 注入，安全
  - `${}`：字符串拼接，有注入风险
  - 能用 `#{}` 就用 `#{}`，`${}` 只在动态表名等特殊场景用

  ---

  **14. MyBatis 的缓存？**

  - 一级缓存：SqlSession 级别，默认开启
  - 二级缓存：namespace 级别，需配置，不建议默认开（多表关联易脏读）

  ---

  **15. SqlSession 是什么？**

  - MyBatis 和数据库的一次"会话"，所有数据库操作都通过它
  - 由 SqlSessionFactory 创建，每次操作新建、用完必须关（不是线程安全）
  - Mapper 接口底层就是 SqlSession，一级缓存也是 SqlSession 级别的

  ---

  **16. 消息队列解决了什么问题？举个例子？**

  - 解决三个问题：解耦、异步、削峰
  - 例子：用户下单后要扣库存、发短信、加积分
    - 不用 MQ：下单要等这三件事全做完才返回，慢
    - 用 MQ：下单后把这三件事扔进 MQ，立刻返回，后面异步处理

  ---

  **17. 消息可能在哪丢失？怎么保证不漏？**

  - 三个地方可能丢：
    - 生产者发消息时丢 → 用确认机制（MQ 收到后回执）
    - MQ 自身丢 → 持久化（消息存磁盘）
    - 消费者处理时丢 → 手动 ACK（处理完才确认）

  ---

  **18. 怎么保证消息不重复消费？（幂等）**

  - 让消费逻辑幂等：同一条消息处理多次，结果一样
  - 实现方式：
    - 用唯一 ID 去重（处理前查一下有没有处理过）
    - 数据库唯一索引
    - 状态机判断（已处理的状态直接跳过）

  ---

  **19. 消息堆积怎么办？**

  - 增加消费者数量
  - 临时扩容消费者
  - 提高消费速度（批量处理、异步）
  - 紧急时先丢弃非核心消息

  ---

  **20. 什么是 CAP 定理？注册中心怎么选？**

  - CAP：一致性、可用性、分区容错性，三者最多同时满足两个。分布式系统必须保证 P，所以在 C 和 A 之间取舍
  - 注册中心选择：
    - CP：Zookeeper、Consul（保证一致性，可能短暂不可用）
    - AP：Eureka、Nacos（默认 AP，保证可用性）

  ---

  **21. 分布式事务有哪些方案？生产怎么选？**

  - 方案：2PC/3PC、TCC、本地消息表、事务消息（RocketMQ）、Saga、最大努力通知
  - 生产选择：
    - 强一致、短事务 → 2PC/TCC
    - 最终一致、高并发 → 本地消息表 / 事务消息 / Saga

  ---

  **22. 什么是幂等性？怎么实现？**

  - 幂等性：同一个操作执行多次，结果和执行一次一样
  - 实现：唯一 ID + 去重表、数据库唯一索引、乐观锁（版本号）、状态机、Token 机制

  ---

  **23. 熔断、降级、限流分别是什么？**

  - 熔断：下游服务故障时，直接切断调用，快速失败，避免拖垮自己
  - 降级：服务不可用时，返回兜底结果（如默认值、缓存），保证核心可用
  - 限流：限制请求速率，超过阈值就拒绝或排队，保护系统不被打垮

  ---

  **24. HashMap 底层数据结构？什么时候链表转红黑树？**

  - 数组 + 链表 + 红黑树
  - 链表长度 ≥ 8 且数组长度 ≥ 64 才树化，否则先扩容

  ---

  **25. 为什么 HashMap 容量是 2 的幂？**

  - 为了用 `(n-1) & hash` 代替取模 `hash % n`，位运算更快
  - `hash` 是 key 经扰动函数 `h ^ (h >>> 16)` 算出的值

  ---

  **26. HashMap 的 put 流程？**

  - ① 计算 hash 定位下标 ② 槽位空→直接放 ③ 有值→链表尾插/树上插入 ④ 超过 `容量 × 0.75`→扩容 2 倍

  ---

  **27. HashMap 1.7 和 1.8 有什么区别？**

  - 1.7 头插法（并发扩容可能成环，导致死循环），1.8 改尾插法（不会成环）+ 引入红黑树（长链表查询从 O(n) 降到 O(log n)）
  - 注意：HashMap 本身仍非线程安全，并发场景要用 ConcurrentHashMap

  ---

  **28. HashMap 是线程安全的吗？ConcurrentHashMap 1.8 怎么保证的？**

  - HashMap 不安全；ConcurrentHashMap 1.8 用 CAS + synchronized，锁粒度是每个桶的节点，比 1.7 的分段锁更细

  ---

  **29. 多线程三大问题是什么？怎么解决？**

  - 原子性：一个操作不能被中途打断 → synchronized / AtomicInteger
  - 可见性：线程改的值其他线程立刻能看到 → volatile
  - 有序性：指令重排导致乱序 → volatile / synchronized

  ---

  **30. synchronized 和 volatile 的区别？**

  - synchronized：解决原子性 + 可见性 + 有序性，作用于方法/代码块，重
  - volatile：仅可见性 + 有序性，不保证原子性，作用于变量，轻
  - `i++` 用 volatile 没用，状态标志位用 volatile 合适

  ---

  **31. 线程池执行流程？**

  - 任务提交 → 核心线程没满？创建核心线程 → 队列没满？进队列 → 没到最大线程数？创建临时线程 → 都满了 → 拒绝策略
  - 关键：先排队、后扩容
  - 拒绝策略：AbortPolicy（默认抛异常）/ CallerRunsPolicy（谁提交谁干）/ DiscardPolicy（丢弃）/ DiscardOldestPolicy（丢最老）

  ---

  **32. 为什么不用 Executors 创建线程池？**

  - `newFixedThreadPool` 和 `newSingleThreadExecutor` 队列无界，任务堆积会 OOM
  - `newCachedThreadPool` 最大线程数无界，可能创建海量线程
  - 要手动 `new ThreadPoolExecutor(...)`，明确队列容量和拒绝策略

  ---

  **33. ThreadLocal 的数据存在哪里？为什么能线程隔离？**

  - 不存 ThreadLocal 对象里，存在当前线程自带的 ThreadLocalMap 中，以 ThreadLocal 实例自身为 key
  - 不同线程调同一个 ThreadLocal，各自写进自己的 map

  ---

  **34. 为什么 ThreadLocalMap 的 key 用弱引用？带来什么问题？**

  - key 用弱引用，让 ThreadLocal 对象外部失引用后能被 GC 回收
  - 问题：key 被回收后留下 `(null, value)` 僵尸 Entry，value 回收不掉
  - 补救：必须 `finally` 里 `remove()`

  ---

  **35. JVM 内存区域有哪些？哪个不会 OOM？**

  - 线程共享：堆、方法区/元空间
  - 线程私有：虚拟机栈、本地方法栈、程序计数器
  - 程序计数器唯一不会 OOM

  ---

  **36. 对象怎么判断是否存活？GC Roots 有哪些？**

  - 可达性分析，从 GC Roots 出发顺着引用找
  - GC Roots：栈里的局部变量、静态变量、常量、native 方法引用
  - 不用引用计数法（循环引用回收不掉）

  ---

  **37. 讲讲对象从出生到老年代的完整过程？**

  - new → Eden → Eden 满触发 Minor GC → 幸存者进 Survivor，年龄+1 → 每熬过一次 Minor GC 年龄+1 → 到 15 岁晋升老年代 → 老年代满触发 Full GC
  - 其他晋升路径：大对象直接进、动态年龄判断、Survivor 装不下直接进

  ---

  **38. Minor GC 和 Full GC 的区别？**

  - Minor GC：只扫新生代，快，Eden 满触发
  - Full GC：整堆，慢、STW 长，老年代满 / System.gc() 触发

  ---

  **39. 新生代为什么用复制算法、老年代用标记-整理？**

  - 新生代存活率低，复制成本低，无碎片
  - 老年代存活率高，复制亏损，用标记-整理

  ---

  **40. 线上 OOM 了怎么排查？**

  - ① 启动参数加 `-XX:+HeapDumpOnOutOfMemoryError` ② `jmap -histo <pid>` 看对象直方图 ③ `jmap -dump` / MAT 分析 .hprof 找引用链 ④ 修代码
  - 常用：`jstat -gcutil <pid> 1000` 看 GC 频率

  ---

  **41. 什么是 IOC？和 DI 什么关系？**

  - IOC：控制反转，对象创建、装配、生命周期的控制权从代码转移到容器，降低耦合
  - DI：依赖注入，是 IOC 的实现方式，如构造器注入、Setter 注入、字段注入

  ---

  **42. 什么是 AOP？四个核心概念？**

  - AOP：把公共逻辑（日志/事务/权限）横切到多个方法
  - 切点（在哪织入）、通知（织入什么）、切面（切点+通知）、连接点（候选方法）

  ---

  **43. AOP 默认 JDK 还是 CGLIB 代理？取决于什么？**

  - 取决于 Bean 有没有实现接口：实现了用 JDK，没实现用 CGLIB
  - JDK：只能代理实现了接口的类；CGLIB：生成目标类的子类，不能代理 final 方法/类

  ---

  **44. Bean 的生命周期？**

  - 实例化(构造) → 属性填充 → @PostConstruct 初始化 → BeanPostProcessor 前后处理 → 使用 → @PreDestroy 销毁
  - 三个钩子：构造 → @PostConstruct → @PreDestroy
  - Bean 默认单例，容器启动时（非懒加载）创建

  ---

  **45. Spring 事务为什么失效？举几个场景？**

  - 原理：Spring 事务基于动态代理，只有经过代理调用才被增强
  - 失效场景：自调用(this.save())、方法不是 public、加在 private/final/static、不是 Bean、异常被 try-catch 吞掉、抛受检异常未配 rollbackFor、传播行为设置错

  ---

  **46. 自调用为什么事务不生效？本质原因是什么？**

  - `this.save()` 直接调目标对象方法，绕过代理，切面没机会拦截 → 事务没开
  - 本质两个字：代理

  ---

  **47. 抛受检异常会回滚吗？怎么配置？**

  - 默认不会，Spring 默认只回滚 RuntimeException 和 Error
  - 要配 `@Transactional(rollbackFor = Exception.class)`

  ---

  **48. 为什么 MySQL 索引用 B+ 树？**

  - 目标是减少磁盘 IO，树越矮越好
  - B+ 树：非叶子只存索引（扇出大，3 层约 2000 万行）；叶子双向链表，范围查询快
  - 红黑树太高；哈希不支持范围；B 树所有节点存数据，树变高

  ---

  **49. 聚簇索引和二级索引的区别？什么是回表？**

  - 聚簇索引（主键）：叶子节点存整行数据
  - 二级索引（普通）：叶子节点存索引列 + 主键值
  - 回表：用二级索引查到主键后，再去聚簇索引查整行

  ---

  **50. 什么是覆盖索引？为什么要避免 SELECT *？**

  - 覆盖索引：索引里已包含查询所需字段，不用回表
  - `SELECT *` 可能无法覆盖索引导致回表，所以只查需要的字段

  ---

  **51. 最左前缀原则是什么？**

  - 联合索引按第一列排，第一列相等再按第二列排
  - `INDEX(name, age)`：`WHERE name=...` 用上，`WHERE name AND age` 用上，`WHERE age` 用不上
  - 范围条件会断档：`WHERE name='张' AND age>18`，age 只能过滤，后面的列索引失效

  ---

  **52. 索引失效的 6 大场景？**

  1. 对索引列做函数/运算 → `date(create_time)=...`
  2. 隐式类型转换 → `WHERE name=123`（varchar 配数字）
  3. 前导模糊查询 → `LIKE '%张'`
  4. 范围条件后面的列 → 断档
  5. `!=` / `NOT IN` / `OR` 非索引列
  6. 联合索引违背最左前缀

  口诀：函数、类型、前置%、范围后、or/!=，联合最左不能破

  ---

  **53. 事务的 ACID？分别靠什么实现？**

  - 原子性：undo log（记录修改前，回滚）
  - 一致性：由其他三个共同保证（总目标）
  - 隔离性：MVCC + 锁
  - 持久性：redo log（记录修改后，崩溃恢复）

  ---

  **54. 脏读、不可重复读、幻读分别是什么？**

  - 脏读：读到未提交的数据
  - 不可重复读：两次读同一行，结果不同（针对 UPDATE）
  - 幻读：两次按条件查，多出数据（针对 INSERT）

  ---

  **55. InnoDB 默认隔离级别是什么？怎么实现可重复读？**

  - RR（可重复读）
  - 快照读靠 MVCC（ReadView 只在第一次查询生成并复用），当前读靠间隙锁/临键锁防幻读
  - **注意：RR 是"基本解决"幻读，不是完全消除**，极端情况仍可能遇到

  ---

  **56. MVCC 怎么实现的？RC 和 RR 的区别？**

  - 每行隐藏字段 DB_TRX_ID + DB_ROLL_PTR，串成版本链
  - ReadView 记录当前活跃事务，沿版本链找回"可见的版本"
  - RC 每次查询生成新 ReadView，RR 只在第一次查询生成并复用 → RR 可重复读

  ---

  **57. 有什么锁？间隙锁干什么用的？**

  - 行锁 Record Lock：锁某一行
  - 间隙锁 Gap Lock：锁两记录间空隙（RR 防幻读靠它）
  - 临键锁 Next-Key Lock：行锁 + 间隙锁（RR 当前读默认单位）

  ---

  **58. explain 怎么看？type=ALL 说明什么？**

  - 先看 type：const > ref > range > index > ALL，出现 ALL = 全表扫 = 索引报废
  - 再看 key：实际用的索引，空 = 没走
  - 最后看 rows：预估扫描行数，越少越好

  ---

  **59. 自增主键为什么能减少页分裂？**

  - 自增主键写入是顺序追加，不会像随机主键那样频繁触发 B+ 树页分裂、造成索引碎片
  - 且主键越短，二级索引叶子节点存的越小、整棵索引树越矮

  ---

  **60. 缓存穿透、击穿、雪崩分别是什么？怎么解决？**

  - 穿透：查根本不存在的数据 → 缓存空值 / 布隆过滤器 / 参数校验
  - 击穿：一个热 key 过期瞬间被高并发打穿 → 互斥锁 / 逻辑过期 / 预热
  - 雪崩：大量 key 同一时刻过期 → 过期时间加随机值 / 多级缓存 / 集群高可用 / 熔断限流降级

  ---

  **61. RDB 和 AOF 的区别？**

  - RDB：快照，周期 dump 整个内存，文件小恢复快，但快照间隙数据会丢
  - AOF：命令日志，追加每条写命令，丢失少，但文件大、重放慢
  - 刷盘策略：always（不丢，最慢）/ everysec（默认，丢1秒）/ no
  - 混合持久化（4.0+）：AOF 重写时把当前快照 RDB 存进 AOF 头，再追加增量 → 恢复快 + 丢得少

  ---

  **62. Redis 分布式锁怎么加？为什么用 SETNX+EX 一个命令？**

  - 加锁：`SET lock "userId" NX EX 10`
  - 必须一个原子命令：不能 setnx 再 expire，两步中间崩了会死锁
  - value 存唯一标识，证明是自己的锁

  ---

  **63. 为什么要用 Lua 脚本解锁？**

  - 保证"判断是我的 + 删除"是原子的
  - `if redis.call('get','lock') == 'userId' then return redis.call('del','lock') else return 0 end`

  ---

  **64. 业务执行太久锁过期了怎么解决？看门狗是什么？**

  - 看门狗机制（Redisson watchDog）：**当加锁时没有显式指定过期时间**（如 `lock.lock()`），Redisson 会启动后台线程定期给锁续期（默认 30 秒续一次，续到 30 秒），业务没完成就不让它过期
  - 如果显式指定了过期时间（如 `lock.lock(10, TimeUnit.SECONDS)`），看门狗不生效

  ---

  **65. 为什么不直接用 setnx 做锁？**

  - 光 setnx 没设过期，宕机就死锁 → 必须 SETNX + EX 原子
  - 只 setnx + expire 两步，中间崩了锁不释放 → 合为一个命令
  - 不校验是谁，可能删到别人的锁 → value 存唯一标识 + Lua 校验

  **66. 反转链表的思路？**

  - 快指针先走 N 步，慢指针再走，快指针到尾时慢指针指向待删节点的前一个

  - 双指针走过各自 + 另一条，相遇即交点

  **71. 二叉树前/中/后序遍历的区别？**

  **73. 最近公共祖先的思路？**

  **74. 最长无重复子串的思路？**

  **75. 快排的思路？**

  - 选基准，分区（小于基准放左，大于放右），递归左右

  - 分治：递归分左右，再合并两个有序数组

  **77. 快排/归并/堆排的复杂度？**

  - 快排：平均 O(n log n)，最坏 O(n²)，空间 O(log n)，不稳定
  - 归并：O(n log n)，空间 O(n)，稳定
  - 堆排：O(n log n)，空间 O(1)，不稳定

  **86. 什么是消息队列的幂等性？怎么实现？**

  **87. 熔断、降级、限流的区别？**

  - 熔断：下游故障时切断调用，快速失败
  - 降级：服务不可用时返回兜底结果
  - 限流：限制请求速率，超阈值拒绝或排队

  ---

  **88. CAP 定理是什么？**

  - 一致性、可用性、分区容错性，三者最多同时满足两个
  - 分布式系统必须保证 P，所以在 C 和 A 之间取舍
  - CP：Zookeeper、Consul；AP：Eureka、Nacos

  ---

  **89. 分布式事务有哪些方案？**

  - 2PC/3PC、TCC、本地消息表、事务消息（RocketMQ）、Saga、最大努力通知
  - 强一致短事务 → 2PC/TCC；最终一致高并发 → 本地消息表/事务消息/Saga

  ---

  **90. 什么是幂等性？怎么实现？**

  - 同一个操作执行多次，结果和执行一次一样
  - 实现：唯一 ID + 去重表、数据库唯一索引、乐观锁、状态机、Token 机制
